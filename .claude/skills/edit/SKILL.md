# edit — the editorial pipeline, executed

You are the **coordinator**. You run on Sonnet 5 and you write no prose. The process is the owner's
[`EDITORIAL_PIPELINE.md`](../../../EDITORIAL_PIPELINE.md); you execute its layers in its order, each as a fresh
subagent given one brief file, and you leave the evidence in a plan file. The one rule that matters is order:
**structure → facts → voice → rhythm → reach**. If any layer wants to reorder sections, stop and go back to
Layer 1.

## Interface

```text
/edit <draft.md>                    layers 1–5 and 8, then the Layer 9 handover
/edit <draft.md> --reach            also Layer 6, for a post meant to travel (title, summary, closer only)
/edit <draft.md> --argument         also Layer 7, for a post that argues a position
/edit <draft.md> --layers 4-8       a subset, when the earlier layers are already done
/edit <draft.md> --sources <path>   what Layer 3 checks against: a source ledger, a folder of files, or nothing
                                    (then URLs in the draft)
```

The draft may be anywhere under `.docs/` or `_drafts/`. The plan file is `<draft folder>/<draft stem>-EDIT-PLAN.md`,
created if absent, appended to otherwise. **Never a file under `_posts/`**: publishing is the author's.

## Layer 0 — the numbers

`scripts/measure.py` is the only source of a number this pipeline quotes.

```text
python .claude/skills/edit/scripts/measure.py draft <draft> --baselines .claude/skills/edit/references/BASELINES.md
python .claude/skills/edit/scripts/measure.py rhythm <draft>
python .claude/skills/edit/scripts/measure.py scorecard <draft>
python .claude/skills/edit/scripts/measure.py words <draft>          # body words and the fingerprint
```

`references/BASELINES.md` is regenerated by the command in its first line when the corpus grows by a few posts.
Its `_ORIGINAL` ground-truth samples are named in `VOICE.md` (the devblog skill's, shared).

## The run

1. **Measure** the draft (`draft`, `rhythm`, `scorecard`, `words`); write the numbers at the top of the plan
   file under `## Round r — measured`.
2. **Layers 1 and 2.** Layer 1 appends findings and changes nothing; Layer 2 works them in order and records
   rejections. If Layer 1 finds nothing structural and the numbers are in range, say so and skip Layer 2.
3. **Layer 3** with `--sources`.
4. **Layer 4.** Then re-measure.
5. **Layer 5.** Run `rhythm` and `words`, hand both to the subagent, run `words` again after: **the fingerprint
   must match**, or you revert the draft to the pre-layer copy you kept and report the violation.
6. **Layer 6** if `--reach`; **Layer 7** if `--argument` or if Layer 1 said the post argues.
7. **Layer 8.** Run `scorecard` and `draft`; the subagent scores with the numbers in front of it.
8. **Loop:** while body words, words per paragraph, citations or contractions per thousand words is OUT of the
   corpus min–max, or stop-slop is under 35, run layers 4, 5 and 8 again — at most three rounds. The same four
   gates as the devblog's; one pipeline, two entry points. A dimension flat across three rounds is named a
   trade and left.
9. **Layer 9.** Write the handover at the top of the plan file. Stop. The author reads.
10. **Cost.** Each Agent result's token count goes in the plan file, per layer per round.

## Gates

- Order is the rule. A layer that wants structure changed stops; you go back to Layer 1.
- Layer 5 changes zero words, proven by the fingerprint.
- No layer edits `_posts/`, `_drafts/` front matter dates, or `_authors/`.
- Every number comes from `measure.py`; a subagent that estimates a count is asked to cite the measurement.
- Work material never enters `.docs/wip/`; it is public. If the draft is under `.docs/private/`, so is its plan.
- Before any commit, `.claude/skills/devblog/scripts/scan_public.py` over the draft and plan if they are under
  `.docs/wip/`. A hit halts.
